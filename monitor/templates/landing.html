ONE WATCHLIST

Built around decisions, not page refreshes.

A monitor is only useful when it turns noisy web changes into something you can act on.

Price intelligence

Detect structured product prices, raw price text, target crossings and every price move with before/after evidence.

Restock signals

Watch availability metadata or a phrase such as “In stock” and alert only when availability changes.

Content diffs

Scope checks to a CSS selector, ignore dynamic text with regex, and keep a dated history instead of sending blind “page changed” alerts.

Weekly briefing

Combine individual events into a seven-day view of what moved, which pages were hottest, and what deserves attention.

Webhook delivery

Native payload formatting for Slack and Discord webhooks, plus generic JSON webhooks for your own automation.

Safer fetching

Private-network URLs are blocked, response size is capped, checks are timed, and the engine records failure instead of silently pretending success.

FAQ

What early access can and cannot do.

Public HTML, JSON, XML and feed-style URLs that can be fetched without login. We test the URL before accepting a paid pilot.

The current shared Railway service intentionally does not execute arbitrary third-party JavaScript in a browser because that needs stronger isolation. The URL probe detects obvious browser-only or blocked pages, and we reject the pilot instead of charging for unreliable monitoring.

The pilot is for managed setup and a working signal, not access to another generic checker. We configure the selector/rule, test noise, verify the external page, and only charge after the setup demonstrates that it works.

The app stores every event in the workspace. It can also deliver to Slack or Discord webhooks, or send a structured JSON webhook into another automation.
